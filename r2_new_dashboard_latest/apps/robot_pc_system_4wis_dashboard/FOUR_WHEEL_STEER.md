# 4WISダッシュボードコピー

`apps/robot_pc_system` をコピーし、`4WIS` タブを追加した版です。

プロジェクト直下でこれを実行します。

```bat
run-robot-dashboard-4wis.cmd
```

シミュレーションでは、実機やゲームパッドがなくてもキーボードで画面上のロボットを動かせます。

- `W` / `S`: 前進 / 後退
- `A` / `D`: 左右移動
- `Q` / `E`: 左右旋回
- `←` / `→`: 左右旋回
- キーボード入力は画面上のシミュレーション専用で、ESP32へ送信されません。
- ゲームパッド接続中でも、キーを押している間はキーボード入力を優先します。

ダッシュボード用Python環境が未作成または壊れている場合は、起動前に `setup-robot-dashboard-4wis.cmd` を自動実行します。

`4WIS` タブには操作が3系統あります。

- 走行入力: `前後`、`左右`、`旋回` スライダーと移動プリセット。
- 個別サーボ角: FL/FR/RL/RR の角度スライダーと姿勢プリセット。
- 実機v29送信: `ARM`、`現在値送信`、`0送信`、`DISARM`。

スライダー操作だけではESP32へ送信しません。
実機へ送る場合は、ESP32実接続、ARM ACK受信、シリアルモニタ切断、緊急停止解除が必要です。
`現在値送信` は v29 NDJSON の `drive` を1回だけ送ります。
PWMは `pc/config.yaml` の `real_4wis.max_pwm` で低出力に制限します。
緊急停止ボタンはv29実接続時に `disarm` を送ります。

シミュレーションタブでは、PCにPS4/ゲームパッドが接続されている場合、ESP32が未接続でも画面上のロボットを動かせます。

- 左スティック/右スティックの軸割り当ては `config/controller_mapping.json` を使います。
- `前後`、`左右`、`旋回` を読み取り、4WISシミュレーション入力として反映します。
- コントローラ入力はESP32へ送信されません。
- コントローラが切断された場合、シミュレーション上の動きは停止します。

シリアル受信またはログ再生にv29 NDJSONテレメトリが含まれる場合は、次の値を優先して表示します。

- `servo_deg`: 4輪のステア角
- `wheel_rpm`: 4輪の実測RPM
- `motor_pwm`: 4輪のPWM値

元の統合ダッシュボードは `apps/robot_pc_system`、元の起動ファイルは `run-robot-dashboard.cmd` のまま残しています。
