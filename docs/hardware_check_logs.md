# 実機確認結果ログ

## 目的

実機クイック確認の結果を後から見返せるように、JSONとTXTの2種類で保存します。

保存しておくことで、チーム内で「いつ、どのCOMポートで、どこまで確認できたか」を共有しやすくなります。

## UIでの確認方法

`実機確認` タブで `実機クイック確認を実行` を押すと、完了時に結果が保存されます。

同じセクションに、前回の結果として次が表示されます。

- 最終実行時刻
- 結果
- COMポート
- 保存先

## 保存先

結果は次に保存されます。

```text
logs\hardware_checks\
```

ファイル名の例:

```text
hardware_check_20260703_153012.json
hardware_check_20260703_153012.txt
```

## JSONとTXTの違い

JSONはプログラムで集計しやすい形式です。

TXTは人が読みやすい形式です。チームへの共有や作業メモにはTXTを使うと便利です。

## 最新結果のコピー

`実機確認` タブの `最新結果をコピー` を押すと、最新のTXT内容をクリップボードへコピーします。

## 結果フォルダを開く

`実機確認` タブの `結果フォルダを開く` を押すと、Windowsのエクスプローラーで `logs\hardware_checks` を開きます。

## 最後のCOMポート記憶

ダッシュボードは、最後に選択または接続したCOMポートを次に保存します。

```text
config\local_settings.json
```

次回起動時に、そのCOMポートがまだ見つかる場合は自動で選択します。見つからない場合はESP32候補を探します。

## COMポートが変わった場合

ESP32を別のUSBポートに挿した場合、COM番号が変わることがあります。

その場合は `COMポート更新` を押して、表示された候補から選び直してください。接続に成功すると、新しいCOMポートが `local_settings.json` に保存されます。

## Gitに保存しない理由

`config\local_settings.json` はPCごとの設定です。チームメンバーやミニPCでCOMポート番号が違うため、Gitには保存しません。

`logs\hardware_checks` の結果ファイルも実行ごとのログなので、通常はGitに保存しません。共有が必要な場合はTXTを別途送ってください。

## CLIで保存する

コマンドラインで保存する場合:

```cmd
.venv\Scripts\python.exe examples\quick_hardware_check.py COM10 --save
```

`--save` を付けた場合だけ、JSONとTXTを `logs\hardware_checks` に保存します。
